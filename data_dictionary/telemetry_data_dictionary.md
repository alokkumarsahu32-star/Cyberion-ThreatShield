# Cyberion ThreatShield — Telemetry Data Dictionary

## 1. Dataset Information

| Property | Verified value |
|---|---|
| Dataset | EVTX-ATTACK-SAMPLES |
| Source repository | https://github.com/sbousseaden/EVTX-ATTACK-SAMPLES |
| Parsed data file | evtx_data.csv |
| Total records | 4,633 |
| Total columns | 326 |
| Primary format | Parsed Windows EVTX event records |
| Dataset period observed | 2019–2020 in inspected samples |

This dictionary is based on the inspected dataset records and field availability.
The dataset contains multiple attack scenarios and Windows event sources.

## 2. Telemetry Source Inventory

| Source | Channel | Records | Role |
|---|---|---:|---|
| Sysmon | Microsoft-Windows-Sysmon/Operational | 2,401 | Primary detection telemetry |
| Windows Security | Security | 1,496 | Primary authentication, object-access and audit telemetry |
| Windows Application | Application | 393 | Supporting application and service telemetry |

The Application channel contains multiple providers, including MsiInstaller,
MSSQLSERVER and Microsoft-Windows-Security-SPP. It is not one homogeneous
application event source.

### Important Sysmon fields

| Field | Meaning | Detection significance |
|---|---|---|
| Image | Executable image path associated with the event | Identify the process involved |
| CommandLine | Command-line string used to start a process | Identify suspicious arguments or commands |
| ParentImage | Parent process executable path | Analyze process ancestry |
| ProcessGuid | Unique process identifier generated by Sysmon | Correlate process events |
| ProcessId | Operating-system process identifier | Support process correlation; may be reused |
| Hashes | File hash values recorded by Sysmon | Support file identification and IOC comparison |
| User | Account associated with the process/event | Identify execution context |
| ImageLoaded | Loaded image or DLL path | Investigate DLL loading |
| DestinationIp | Remote destination IP address | Network investigation and IOC matching |
| DestinationPort | Remote destination port | Identify network service/connection patterns |
| Protocol | Network protocol | Distinguish connection types |
| Initiated | Indicates connection initiation direction | Add context to network activity |
| SourceImage | Source process in a process-access event | Identify the accessing process |
| TargetImage | Target process in a process-access event | Identify the accessed process |
| GrantedAccess | Access rights requested/granted in process access | Investigate potentially sensitive process access |
| TargetFilename | File path created by the process | Investigate file creation |
| TargetObject | Registry object path | Investigate registry changes |
| EventType | Registry operation type | Distinguish registry operations |
| Details | Registry value details | Understand the recorded registry change |

## 5. Application Event Reference

The Application channel contains different providers. These records are treated
as supporting telemetry rather than a single uniform source.

| Event ID | Observed provider | Dataset observation | Potential use |
|---:|---|---|---|
| 1040 | Security-SPP in inspected sample | Event record with Binary and EventSourceName | Provider-specific event investigation |
| 1042 | MsiInstaller in inspected sample | Installer-related event record | Installer activity investigation |
| 18456 | MSSQLSERVER | SQL Server login failure scenario in dataset filename | Database authentication investigation |
| 15457 | MSSQLSERVER | SQL Server configuration-change scenario in dataset filename | Database configuration monitoring |

Application event payloads inspected here do not expose the same process and
network fields as the selected Sysmon records. Provider-specific parsing is
required before engineering rules for these events.

## 7. Data Quality and Limitations

1. The CSV contains 326 columns, but many fields are empty for individual events.
2. Field availability varies by event ID and provider.
3. The dataset includes multiple machines, scenarios and timestamps.
4. The CSV contains both `ProcessID` and `ProcessId`. Their names must be
   preserved separately during parsing.
5. The CSV also contains case-variant field names such as `Guid` and
   `ProcessGuid`; field names must not be normalized carelessly.
6. The first CSV column has no meaningful header and is imported as an
   unnamed/index column.
7. `EVTX_Tactic` is dataset metadata. It should not be treated as independent
   proof that a detection rule correctly maps to an ATT&CK technique.
8. An event's presence does not by itself prove malicious activity.
9. The inspected samples are not sufficient to claim that every proposed
   detection rule has been tested.
10. Application channel events require provider-specific interpretation.

## 8. Detection Engineering Implications

- Prioritize Sysmon process creation, network connection, image loading,
  process access, file creation and registry events.
- Use Windows Security events for authentication, process creation,
  object access, network share access and audit-log investigation.
- Use Application events selectively where the provider and payload support
  a defensible detection use-case.
- Correlate events using timestamps, host identifiers, process identifiers,
  process GUIDs and account fields where available.
- Document missing fields and false-positive considerations for every rule.
- Test each Sigma rule against the actual selected records before marking it tested.

## 9. Evidence Status

This document records dataset inventory, inspected event IDs and observed fields.
It is an initial data dictionary, not a claim that detection rules or hunts
have been completed.
